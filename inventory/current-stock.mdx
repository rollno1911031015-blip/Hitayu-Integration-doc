The Inventory module shows stock held in Hitayu CRM for product variants, warehouse locations, recent stock ledger activity, and warehouse stock audits. The page is served from the Admin Inventory route and is divided into dashboard, current-stock, warehouse, stock-activity, and stock-audit segments.

## Navigating to Inventory

Go to **Admin -> Inventory**. The inventory segment is included in the URL:

| Segment | URL | What it shows |
|---|---|---|
| **Dashboard** | `/admin/inventory/dashboard` | Inventory KPIs, stock alerts, and recent activity |
| **Current Stock** | `/admin/inventory/current-stock` | Product variant stock, warehouse quantities, and stock status |
| **Warehouses** | `/admin/inventory/warehouses` | Shopify warehouse locations and their stock totals |
| **Stock Activity** | `/admin/inventory/stock-activity` | The latest 50 stock ledger entries |
| **Stock Audit** | `/admin/inventory/stock-audit` | Warehouse count sheets and completed audit records |

<Note>
  Access is permission controlled. The dashboard requires `dashboard.inventory`. Inventory segments require one of `inventory.current_stock`, `inventory.stock_ledger`, `inventory.stock_audit`, or `orders.view`. Actions such as adding stock, syncing warehouses, and completing audits require additional management permissions.
</Note>

## Inventory Dashboard

The dashboard gives a quick summary of inventory health.

| Area | What it displays |
|---|---|
| **Hitayu Inventory Control** | Total ready-to-sell quantity from available stock |
| **KPI cards** | Total Stock, Available Stock, Reserved Stock, and Out Stock |
| **Inventory Actions** | Links to Current Stock, Warehouses, Stock Activity, and Stock Audit |
| **Stock Attention** | Up to 8 low-stock or out-of-stock variants |
| **Stock Activity** | Up to 8 recent stock ledger movements |

The dashboard data is calculated from product variants and stock ledger rows loaded by the inventory service.

## Current Stock

Open **Admin -> Inventory -> Current Stock** (`/admin/inventory/current-stock`) to view variant-level stock.

### Filters

| Filter | Behavior |
|---|---|
| **Search** | Matches product name, product SKU, variant name, or variant SKU |
| **Stock Status** | Filters by Healthy, Low Stock, or Out of Stock |
| **Reset** | Returns to the unfiltered current-stock segment |

### Columns

| Column | Description |
|---|---|
| **Product** | Product name, with the variant name below it. If the variant has no name, the page shows "Default variant". |
| **SKU** | Variant SKU, falling back to the product SKU when needed |
| **Warehouses** | Up to two warehouse quantity lines. If more warehouses hold stock, the row shows a "+ more" count. |
| **Total Stock** | The variant `total_stock` value |
| **Reserved** | The variant `reserved_stock` value |
| **Out** | The variant `out_stock` value |
| **Available** | The variant `available_stock` value |
| **Status** | Healthy, Low Stock, or Out of Stock |

### Stock Status Rules

Stock status is calculated from available stock:

| Available stock | Status |
|---:|---|
| `0` or less | Out of Stock |
| `1` to `5` | Low Stock |
| `6` or more | Healthy |

## Add 1000 Stock

Users with `inventory.manage`, `inventory.current_stock`, and `inventory.stock_ledger` can see the **Add Stock to Active Products** panel on the Current Stock page.

When **Add 1000 Stock** is confirmed:

- The system adds `1000` units to every product variant whose product status is `active`.
- Each variant update is written through the inventory stock service.
- A Stock Activity entry is created for each updated variant.
- The source used for the change is **CRM Bulk Stock**.
- The user is redirected to `/admin/inventory/stock-activity` with a success message.

The form posts to `/admin/inventory/bootstrap-crm-stock` with `quantity=1000` and `mode=increment`.

<Warning>
  The visible action increases active variant stock by 1000 units. It is not a Shiprocket import and it is not limited to one warehouse row.
</Warning>

## Warehouses

Open **Admin -> Inventory -> Warehouses** (`/admin/inventory/warehouses`) to view warehouse locations.

### Warehouse columns

| Column | Description |
|---|---|
| **Warehouse** | Warehouse name and code |
| **Shopify Location ID** | The linked Shopify location ID, if available |
| **Address** | Pickup location and pincode |
| **Stock** | Total quantity across stock rows for the warehouse |
| **Stock Lines** | Count of non-zero stock rows |
| **Status** | Active or Inactive |

### Sync Warehouses

The **Sync Warehouses** button appears on the Warehouses segment. It calls the Shopify warehouse sync flow and returns a success message with the number of synced warehouse locations and channels.

<Note>
  Warehouse sync requires `inventory.manage`, `inventory.warehouses`, `inventory.current_stock`, and `settings.integrations`. The code validates Shopify Admin access before syncing locations.
</Note>

## Stock Activity

Open **Admin -> Inventory -> Stock Activity** (`/admin/inventory/stock-activity`) to review stock ledger rows. The page shows the latest 50 entries.

### Filters

| Filter | Behavior |
|---|---|
| **Search** | Matches product name, SKU, or reference ID |
| **Source Channel** | Filters by an existing source channel from stock ledger records |
| **Reset** | Returns to the unfiltered stock-activity segment |

### Columns

| Column | Description |
|---|---|
| **Date & Time** | Ledger creation date and time |
| **Product** | Product name, with the note below it when available |
| **SKU** | Ledger SKU |
| **Source** | Ledger source channel |
| **Warehouse** | Linked warehouse name, or `-` |
| **Reference** | Order link when the ledger belongs to an order, otherwise the reference ID |
| **Previous** | Previous stock balance |
| **Changed** | Quantity changed, shown as `+` for credit and `-` for debit |
| **Updated** | Updated stock balance |
| **Updated By** | User name, or the actor type when no user is linked |

## Stock Audit

Open **Admin -> Inventory -> Stock Audit** (`/admin/inventory/stock-audit`) to create and complete warehouse count sheets.

### Create an audit

Users with `inventory.stock_audit` and `inventory.manage` can create a stock audit by selecting a warehouse and optionally entering notes.

When an audit is created:

- The system creates an audit number in the `SA-YYYYMMDDHHMMSS-###` format.
- The audit starts in `draft` status.
- Active product variants are added as audit items.
- Each item's system quantity is taken from that variant's stock in the selected warehouse.

### Update and complete an audit

Draft audits allow counted quantity and remarks to be saved for each line. Variance is calculated as:

```text
counted quantity - system quantity
```

An audit cannot be completed until every audit item has a counted quantity. On completion, only lines with a variance are posted to stock through the inventory stock service. The audit status is then changed to `completed`, with completed user and completed time recorded.

<Note>
  Completed audits cannot be changed.
</Note>
