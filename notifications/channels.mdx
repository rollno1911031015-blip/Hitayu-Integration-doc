Hitayu ERP supports three outbound notification channels: **WhatsApp** (via the Meta Cloud API), **SMS** (via SMS Wale), and **push notifications** (via Firebase Cloud Messaging for the mobile app). Each channel can be enabled or disabled independently in Settings, so you can run only the channels your business needs.

---

## WhatsApp Channel

WhatsApp messages are sent through the **Meta Cloud API** as plain-text messages to the customer's phone number. This channel is used for payment link delivery and order confirmation notifications.

### How It Works

When an event fires (e.g., order confirmed, payment link generated), Hitayu builds the message text, substitutes the variable placeholders with real data, and sends the message via the Meta Cloud API to the customer's phone number. The provider returns a **message ID** which is stored in the notification log.

After delivery, Meta sends a **status callback** to Hitayu at:

```
POST /api/webhooks/whatsapp/status
```

This webhook updates the notification log status from `sent` to `delivered` or `read` (depending on what Meta reports), giving you end-to-end delivery confirmation.

### Required Configuration

Go to **Settings -> Integrations -> WhatsApp** and enter:

| Setting | Description |
|---|---|
| **Provider** | Set to `meta` (the Meta Cloud API provider) |
| **Access Token** | Your Meta app's permanent or long-lived access token |
| **Phone Number ID** | The WhatsApp Phone Number ID from Meta Business Manager |
| **Verify Token** | A secret string you define; Meta sends this when verifying the webhook endpoint |

<Warning>
  WhatsApp will only deliver messages if all four credentials above are filled in. If any required credential is missing, Hitayu falls back to generating a manual `wa.me` link in the notification log so staff can copy-paste the message to the customer manually.
</Warning>

### Enabling and Disabling WhatsApp Notifications

WhatsApp delivery for each event type is controlled by toggle switches in **Settings -> Integrations -> Notifications**:

- **Payment Links By WhatsApp** - toggle on/off sending payment links via WhatsApp
- **Order Received By WhatsApp** - toggle on/off sending order confirmations via WhatsApp

When a toggle is off, Hitayu skips WhatsApp delivery for that event and records the log entry without attempting a send.

## SMS Channel

The SMS channel sends transactional text messages to customers via **SMS Wale** (`smswala`), an API-key based provider.

### How It Works

On an event trigger, Hitayu builds the SMS message text, substitutes variables, and sends the message to the customer's phone via the SMS Wale API. The provider response (including a message ID or error code) is stored in the notification log.

For delivery status callbacks, Hitayu receives provider webhooks at:

```
POST /api/webhooks/sms/status
```

The webhook updates the log entry with the final delivery status reported by the SMS gateway.

### Required Configuration

Go to **Settings -> Integrations -> SMS** and fill in the SMS Wale settings:

| Setting | Description |
|---|---|
| **Provider** | `smswala` |
| **API URL** | The SMS Wale API endpoint URL |
| **API Key** | Your SMS Wale account API key |
| **Campaign** | Campaign ID assigned by SMS Wale |
| **Route ID** | Routing identifier for transactional messages |
| **Sender ID** | Your registered DLT sender ID (e.g., `HTYUHC`) |
| **PE ID** | Your Principal Entity ID for TRAI DLT compliance |
| **Payment Link Template ID** | DLT-registered template ID for payment link messages (optional) |
| **Order Received Template ID** | DLT-registered template ID for order confirmation messages (optional) |

### Enabling and Disabling SMS Notifications

SMS delivery per event is controlled by toggle switches in **Settings -> Integrations -> Notifications**:

- **Payment Links By SMS** - toggle on/off sending payment links via SMS
- **Order Received By SMS** - toggle on/off sending order confirmations via SMS

<Tip>
  The **SMS Wale API URL** defaults to `https://sms.smswala.in/app/smsapi/index.php`. Update this only if SMS Wale provides you with a different endpoint.
</Tip>

## Push Notifications (FCM)

Push notifications are delivered to **staff members' mobile devices** using **Firebase Cloud Messaging (FCM)**. They are not sent to customers.

### What Triggers Push Notifications

| Event | Who receives it |
|---|---|
| **Call Answered** | The agent assigned to the IVR call |
| **Call Missed** | The agent who was expected to receive the call |
| **Payment Received** | Configured staff roles (as set by your admin) |

### How It Works

When a staff member logs in on the mobile app, their device registers a **device token** with Hitayu (`POST /device-tokens`). When a push event fires, Hitayu sends the notification payload to that device token via FCM. If the device token is stale or invalid, the delivery fails silently - no error is surfaced to the customer.

### Configuration

FCM credentials (Server Key / Service Account JSON) are configured by your system administrator at the environment level. There is no in-app settings card for FCM - contact your administrator if push notifications are not arriving on mobile devices.

## Staff Bell Notifications

In addition to the three outbound channels above, Hitayu has an **in-app notification bell** visible to all logged-in staff in the top header bar.

- The bell icon shows an **unread count badge** for pending notifications
- Click the bell to open the notification dropdown
- Click any notification to mark it as read, or use **Mark All Read** to clear the badge
- Notifications include: new IVR calls, missed calls, order assignments, payment events, and system alerts

These bell notifications are internal only and do not use WhatsApp, SMS, or FCM.

## Delivery Status Reference

Notification logs (visible under **Notifications** in the sidebar) use the following statuses:

| Status | Meaning |
|---|---|
| `queued` | Notification has been created but not yet sent |
| `sent` | Hitayu successfully dispatched to the provider |
| `delivered` | Provider confirmed the message reached the recipient's device |
| `read` | Recipient opened the message (WhatsApp only) |
| `failed` | Provider returned an error; check the provider response column |

<Note>
  Not all providers report `delivered` or `read` statuses. SMS Wale typically only confirms `sent`. WhatsApp via Meta Cloud API provides read receipts when the recipient has read receipts enabled.
</Note>
