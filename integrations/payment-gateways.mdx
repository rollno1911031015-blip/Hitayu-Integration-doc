Hitayu ERP supports three payment gateways — PayU, Razorpay, and Cashfree. Only one gateway is active at a time, but credentials for all three can be stored in Settings so you can switch between them without reconfiguration. When a customer pays through a payment link, Hitayu reconciles the transaction automatically against the relevant order and updates the payment status — no manual data entry required.

---

## Selecting Your Active Gateway

<Steps>
  <Step title="Open Payment Gateway settings">
    Go to **Settings → Integrations → Payment Gateways**.
  </Step>
  <Step title="Choose your active provider">
    Select your preferred gateway from the **Active Payment Provider** dropdown. The options are:

    | Option | Gateway |
    |---|---|
    | `payu` | PayU |
    | `razorpay` | Razorpay |
    | `cashfree` | Cashfree |

    Only the selected provider will be used when generating payment links and processing transactions.
  </Step>
  <Step title="Fill in the credentials for your chosen gateway">
    See the sections below for the exact fields each gateway requires.
  </Step>
</Steps>

<Warning>
  Changing the active gateway mid-operation does not affect transactions already in progress. Any payment links generated before the switch will continue to use the gateway they were created with. Switch gateways only between billing cycles or before going live.
</Warning>

## PayU

PayU is a popular payment gateway in India, supporting net banking, UPI, credit/debit cards, and EMI.

### Required Credentials

| Field | Where to Find It | Notes |
|---|---|---|
| **Merchant Key** | PayU Dashboard → Profile → Merchant Key | Unique identifier for your merchant account |
| **Merchant Salt** | PayU Dashboard → Profile → Salt | Used to generate request hashes |
| **Base URL** | PayU Dashboard or PayU docs | Use `https://test.payu.in/_payment` for sandbox; `https://secure.payu.in/_payment` for production |

### Webhook Endpoint

Register the following URL in your PayU merchant dashboard under **Webhook / Callback settings**:

```text
POST https://your-hitayu-domain.com/api/webhooks/payment/payu
```

<Note>
  PayU sends payment success and failure callbacks to this endpoint. Hitayu verifies the hash using your Merchant Salt before updating any order record.
</Note>

### Test vs. Production Mode

| Mode | Base URL |
|---|---|
| **Sandbox (Test)** | `https://test.payu.in/_payment` |
| **Production** | `https://secure.payu.in/_payment` |

Change the **Base URL** field in Hitayu when you are ready to go live. Do not mix test and production keys.

## Razorpay

Razorpay supports UPI, cards, net banking, wallets, and BNPL across web and mobile.

### Required Credentials

| Field | Where to Find It | Notes |
|---|---|---|
| **Key ID** | Razorpay Dashboard → Settings → API Keys | Starts with `rzp_test_` (test) or `rzp_live_` (production) |
| **Key Secret** | Razorpay Dashboard → Settings → API Keys | Generated alongside the Key ID |
| **Webhook Secret** | Razorpay Dashboard → Settings → Webhooks | Used to verify the `X-Razorpay-Signature` header |

### Webhook Endpoint

Register the following URL in your Razorpay Dashboard under **Settings → Webhooks → Add New Webhook**:

```text
POST https://your-hitayu-domain.com/api/webhooks/payment/razorpay
```

Enable the following event subscriptions on that webhook in Razorpay:
- `payment.captured`
- `payment.failed`
- `refund.created`
- `order.paid`

<Tip>
  Copy the **Webhook Secret** from Razorpay's webhook creation screen and paste it into the **Razorpay Webhook Secret** field in Hitayu. This is separate from your Key Secret and is used exclusively for verifying inbound webhook signatures.
</Tip>

### Test vs. Production Mode

Use `rzp_test_` keys for sandbox testing and `rzp_live_` keys in production. The Razorpay API endpoint automatically routes based on the key prefix — there is no separate URL to change.

## Cashfree

Cashfree offers payment collection through UPI, cards, net banking, and Cashfree's own payment pages.

### Required Credentials

| Field | Where to Find It | Notes |
|---|---|---|
| **App ID** | Cashfree Dashboard → Developers → API Keys | Your merchant App ID |
| **Secret Key** | Cashfree Dashboard → Developers → API Keys | Your merchant Secret Key |
| **Environment** | Set in Hitayu settings | `sandbox` for testing, `production` for live |
| **API Version** | Defaults to `2023-08-01` | Only change if instructed by Hitayu support |

### Webhook Endpoint

Register the following URL in your Cashfree Dashboard under **Developers → Webhooks → Add Endpoint**:

```text
POST https://your-hitayu-domain.com/api/webhooks/payment/cashfree
```

Enable the following event types:
- `PAYMENT_SUCCESS`
- `PAYMENT_FAILED`
- `PAYMENT_PENDING`
- `REFUND_STATUS`

### Test vs. Production Mode

| Mode | Environment Value |
|---|---|
| **Sandbox** | `sandbox` |
| **Production** | `production` |

Set the **Environment** field in Hitayu to `production` when you are ready to process real payments. Cashfree uses separate App IDs for sandbox and production — make sure you switch both the environment value and the credentials at the same time.

## How Payment Reconciliation Works

When a customer completes payment on any supported gateway:

1. The gateway sends a signed webhook payload to Hitayu's payment endpoint.
2. Hitayu verifies the signature using your stored secret/salt/webhook-secret.
3. The matching order's payment status is updated (e.g., **Paid**, **Failed**, **Refunded**).
4. A `payment_transaction` record is created for audit and reporting purposes.
5. If the payment is successful, the order automatically advances to the next lifecycle stage.

All webhooks are idempotent — if the same payment event is delivered more than once (which gateways sometimes do), Hitayu detects the duplicate and ignores it without creating duplicate records.

## Troubleshooting

| Symptom | Likely Cause | Fix |
|---|---|---|
| Payments not reconciling | Webhook not registered with the gateway | Add the Hitayu webhook URL in your gateway dashboard |
| Signature verification failure | Webhook secret mismatch | Re-copy the webhook secret from your gateway into Hitayu |
| Test payments appearing in live reports | Using test keys in production | Switch to production keys and update the Environment/Base URL |
| Payment status stuck on Pending | Queue worker not running | Ask your team to verify `php artisan queue:work` is active |
| Wrong gateway processing payments | Active provider not updated | Check **Active Payment Provider** in Settings → Integrations |
