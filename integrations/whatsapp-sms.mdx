Hitayu CRM can send customer notifications through WhatsApp, SMS, and email. WhatsApp delivery uses Meta WhatsApp credentials. SMS delivery uses SMS Wale credentials. Exotel is used by the IVR/calling integration, not by the SMS sender in the current code.

## Where to Configure

Open **Settings -> Integrations** (`/settings/integrations`) and use the **WhatsApp**, **SMS**, and **Notifications** provider cards.

Changing these settings requires `settings.integrations.manage` or `settings.integrations`.

## WhatsApp

The WhatsApp card stores these credential keys:

| Field | Required | Secret |
|---|---:|---:|
| Provider | Yes | No |
| Access Token | Yes | Yes |
| Phone Number ID | Yes | No |
| Verify Token | Yes | Yes |

The notification service sends WhatsApp messages through the Meta messages API when access token and phone number ID are configured. Messages are sent as text messages.

If WhatsApp credentials are not configured, the service marks the log as sent with a manual WhatsApp fallback URL in the provider response.

## SMS Wale

The SMS card stores SMS Wale settings:

| Field | Required | Secret |
|---|---:|---:|
| Provider | Yes | No |
| SMS Wale API URL | Yes | No |
| SMS Wale API Key | Yes | Yes |
| Campaign | Yes | No |
| Route ID | Yes | No |
| Sender ID | Yes | No |
| PE ID | Yes | No |
| Payment Link Template ID | No | No |
| Order Received Template ID | No | No |

SMS sends fail when URL, key, campaign, route ID, sender ID, or PE ID is missing.

The service accepts Indian mobile numbers. Ten-digit numbers are prefixed with `91`; twelve-digit numbers beginning with `91` are used as submitted.

## Notification Gates

The Notifications provider controls whether payment link and order received messages are sent.

| Gate |
|---|
| Send Payment Links |
| Payment Links By SMS |
| Payment Links By WhatsApp |
| Payment Links By Email |
| Send Order Received Confirmation |
| Order Received By SMS |
| Order Received By WhatsApp |
| Order Received By Email |

The **Payment Link Delivery Mode** choice supports:

| Option | Behavior |
|---|---|
| Direct | Sends through the notification service immediately |
| Queue | Dispatches a queued notification job |

## Notification Events

The notification text is generated in code for:

| Event | Message purpose |
|---|---|
| `payment_link` and other default events | Sends payment amount, reference number, and payment link |
| `order_received` | Sends order number, advance paid, balance due, estimated delivery, and tracking link |

## Status Webhooks

The API routes include:

| Method | Endpoint | Purpose |
|---|---|---|
| POST | `/api/webhooks/whatsapp/status` | Dispatches a WhatsApp status webhook processing job |
| POST | `/api/webhooks/sms/status` | Dispatches an SMS status webhook processing job |

Status payloads are recorded as notification logs by the provider status service.
