Hitayu ERP is built to work alongside the tools your e-commerce business already relies on. Rather than replacing your Shopify store, your shipping partner, or your payment gateway, Hitayu connects to all of them — pulling orders in automatically, pushing shipment updates back out, and keeping your team informed through WhatsApp, SMS, and calling workflows. Every integration is configured in one place and takes effect across the entire platform.

## Where to Configure Integrations

All integrations are managed from a single screen inside the app. Navigate to **Settings → Integrations** to view, configure, and test each connection.

<Note>
  You need **Admin** or **Settings Manager** permissions to access the Integrations screen. Contact your account owner if you do not see this menu item.
</Note>

Each integration card on that screen shows a status badge:

| Status | Meaning |
|---|---|
| **Ready** | All required credentials are saved and the connection has been verified. |
| **Missing** | One or more required fields are empty. The integration will not function until they are filled in. |
| **Disabled** | Credentials are saved but the integration has been manually turned off via its toggle. |

## How Integrations Work

Hitayu ERP uses a queue-based integration architecture. When an external platform sends a webhook (for example, Shopify notifying Hitayu that a new order was placed), Hitayu accepts the request, logs it immediately, and then processes the event asynchronously in the background. This means:

- **Your storefront is never slowed down** by ERP processing delays.
- **Duplicate events are safely ignored** — all webhooks are idempotent, so re-delivered payloads do not create duplicate records.
- **Failed jobs are retried automatically** — if a downstream service is temporarily unavailable, Hitayu will re-attempt processing without any manual intervention.

<Tip>
  For the smoothest experience, ensure your queue worker is running continuously in production. Ask your technical team to configure a process supervisor (such as Supervisor on Linux) to keep `php artisan queue:work` alive.
</Tip>

## Integration Setup Checklist

Use this checklist when going live with a new integration:

<Steps>
  <Step title="Gather Credentials">
    Collect all API keys, secrets, and tokens from the external platform's developer or settings dashboard before opening Hitayu.
  </Step>
  <Step title="Enter Credentials in Hitayu">
    Go to **Settings → Integrations**, open the relevant integration card, and fill in every required field. Save the form.
  </Step>
  <Step title="Register Webhook URLs">
    Copy the webhook endpoint URLs shown in Hitayu and paste them into the external platform's webhook configuration. See each integration's page for the exact URLs and topics.
  </Step>
  <Step title="Verify the Status Badge">
    Return to **Settings → Integrations** and confirm the card now shows a **Ready** status badge.
  </Step>
  <Step title="Run a Test Event">
    Trigger a test event from the external platform (e.g., place a test order in Shopify) and confirm it appears in Hitayu within a few seconds.
  </Step>
</Steps>

## Webhook Security

Every inbound webhook endpoint in Hitayu is protected by signature or token verification specific to the sending platform:

- **Shopify** webhooks are verified using HMAC-SHA256 signatures computed against your `SHOPIFY_WEBHOOK_SECRET`.
- **Shiprocket** tracking webhooks optionally require a bearer token set via `SHIPROCKET_WEBHOOK_TOKEN`.
- **Payment** webhooks (Razorpay, Cashfree, PayU) use each gateway's own signature scheme.

Requests that fail signature verification are rejected with an HTTP `401` response and logged for audit purposes. See the [Webhook Reference](/integrations/webhooks) for full details.
